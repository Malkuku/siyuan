# Handoff

Handoff 是临时交接单，用于让另一工作区、Chat 或 agent 继续执行任务；不是长期事实源。仅在跨执行上下文交接时使用。已有双方可访问且足以执行的正式任务，无须重复生成。

## 确定交接范围

先确认接收方能访问的上下文：

- **独立上下文**：无法访问发送方工作区、代码、Spec 或历史对话。Handoff 必须自包含必要背景、已确认结论及跨边界契约；不得依赖发送方内部路径，不猜测或调查接收方的内部实现。
- **共享工作区**：能够访问正式工件，但缺少当前 Chat 历史。引用已有 Spec、API、任务或代码，只补充尚未记录、但接续任务必需的决策和约束；不搬运聊天过程。

**写清已确定的跨边界契约，不替接收方设计内部实现。**

- 契约按实际任务写明：调用入口、方法、字段与结构、响应及错误语义、鉴权、默认值与兼容行为、事件协议、必要的版本或部署顺序等；未知事项标为待确认，不自行补全。
- 接收方自行决定：类和文件、封装与状态管理、内部查询和存储方式、重试与并发策略、内部重构等。仅在这些细节本身已构成跨边界约束时写入。

例如，已确定文件代理接口 `GET /files/{id}`，不存在时返回 `404`，就明确要求接收方通过该接口取文件；既不能只写“适配文件读取”，也不指定修改哪个前端组件或新增何种封装。

## 编写内容

只写接收方执行和验收所需的信息，按需组织章节：

1. **交接目标**：来源、接收方、任务及必要背景。
2. **已确认结论与契约**：变化前后、关键字段或行为、兼容约束；共享工作区可引用正式工件。
3. **接收方任务**：要完成的修改、范围及必须保持的行为。
4. **验收标准**：接收方可独立验证的结果，以及尚待确认的问题。

避免复制发送方实现过程、无关的内部修改或 agent 分工。字段、接口、枚举、行为发生变化时，优先写清修改前后差异，保留必要的默认值、空值、错误和部署语义。

## 文件与生命周期

- 默认在当前工作区根目录使用 `HANDOFF-xxxx.md`；同一交接更新已有文件，不同接收方分别建文件，不混合任务。
- **不进入 Git**：在 `.gitignore` 中排除 `HANDOFF.md` 和 `HANDOFF-*.md`；已被跟踪的文件先取消跟踪。
- **不进入任何索引**：不得加入 `AGENTS.md`、README、任务或文档索引；正式工件也不得反向引用 Handoff。Handoff 可以引用正式工件。
- 接收方完成并验收后，将仍有效的结论写入 Spec、ADR、API、任务、代码或测试等正式工件，随后删除 Handoff。
