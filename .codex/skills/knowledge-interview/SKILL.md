# 知识问答

通过面试、答辩式的连续问答，帮助用户检验理解或提取经验；形成准确、可追溯、可接续的知识记录。不要把问答变成固定题库，也不要把用户或 Agent 的陈述直接视为事实。

## 开始

1. 识别目标：**知识巩固**侧重独立作答与应用能力；**知识提取**侧重挖掘用户经验、设计理由与隐含前提。两者可在对话中自然切换。
2. 明确主题与本次范围；读取用户提供或当前工作区已有的相关材料、知识记录与近期问答证据，按需渐进读取，不默认全量遍历。
3. 将材料能直接确认的事实先查明；把资料中的事实、用户陈述、Agent 推断及待验证问题区分开。材料不支持的结论不得补造。
4. 在可写工作区创建或恢复**本次主题的独立临时草稿**；已有同名草稿时先检查归属，禁止覆盖其他讨论。临时草稿不加入正式知识索引；在使用 Git 的工作区按其临时文件规则排除跟踪。无文件写入能力时维护对话内结构化记录，在结束时完整输出，明确未落盘。

## 连续问答

- 一轮聚焦一个最有价值的问题，留出用户独立回答的机会。根据回答和已有证据，动态选择基础概念、设计依据、实现机制、边界条件、反例或应用场景。
- 知识提取优先追问材料中缺失的个人经验、判断和取舍；知识巩固优先检验是否能独立解释并应用。材料已明确的事实不重复要求用户背诵，除非本次目标就是考察它。
- **即时质疑与纠错**：发现实质错误、事实冲突或重要疑点，及时指出并说明依据；可给一次自行修正机会。仍有偏差时直接讲解准确机制，必要时换场景检查理解，不无限逼问。
- 可核实的技术事实优先结合代码、测试、规范或权威资料验证；版本差异和证据不足的内容标为待验证。设计取舍应评价前提、代价与适用条件，不将主观偏好冒充唯一答案。
- 明确区分**独立答对、提示后答对、听完讲解表示认同、实践验证**。Agent 讲过的内容不代表用户已经掌握；用户回答错误仍是有价值的学习证据。
- 不为了题量、难度或追问形式而延长对话。关键知识已覆盖时主动概括进度、理解缺口与遗留问题，提出收束或切换建议，由用户决定继续还是结束；用户可随时暂停。

## 持续草稿

每出现实质新信息就更新草稿中的当前状态，优先替换旧结论而非追加聊天流水账。按实际内容保留：

- 主题、目标、材料入口与覆盖进度。
- **当前知识**：已核实的结论、关键理由、适用条件和来源；尚不确定的内容另标待验证。
- **用户理解证据**：有代表性的原始回答或准确摘要、问题、提示程度、日期及后续验证结果。后来的正确讲解不得覆盖历史表现。
- 未解决问题、下一轮适合追问的方向，以及恢复讨论所需上下文。

草稿应足以让其他 Agent 不依赖原始聊天继续，但避免复制冗长材料、重复事实和失效的探索过程。用户暂停时保存可恢复状态；无落盘能力则提供可复制的草稿。

## 收束与交接

- 对照本次目标，概括覆盖范围、已核实知识、用户掌握证据、理解缺口及仍待验证的问题；未经实际考察的领域不得标记为不会，也不得虚构学习记录。
- 输出**可复用的知识记录**，保留必要事实、理由、边界和来源；问答表现作为独立证据保存，不混入权威知识正文。
- 在 Atlas 中遵守已有知识模块的学习事件、复习事件、知识条目与索引规则；用户明确发起复习即授权保存该次复习摘要。普通聊天中发现值得入库的知识，先建议并取得确认。未经授权不改动跨工作区文件或计划。
- 其他工作区遵守当地文件组织与保存规则；无规则时提供独立 Markdown 记录，不假设用户使用 Atlas。
- 仅当需要另一个执行上下文继续处理任务时，优先按已有 `handoff` Skill 规范另生成临时交接单。知识记录是可长期保存的成果，Handoff 只是临时传递载体，二者不要混用。正式内容承接后清理无用草稿；未交接完成的草稿保留供恢复。
