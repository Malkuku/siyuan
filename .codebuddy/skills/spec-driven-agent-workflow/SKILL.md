# Spec 驱动 Agent 工作流

以仓库当前 Spec 和实现为依据，选择完成任务所需的最小流程。本 Skill 管理工作流，不保存项目事实。

## 事实与导航

- 长期产品、业务和架构事实写入对应 Spec；`AI2AI/API` 维护接口、协议、数据和持久化契约；迭代任务记录实施决定与验收；代码和测试提供实现与验证证据。
- 先读 `AI2AI/索引`，再按需阅读 Spec、API、任务和源码。索引只登记真实存在的导航、当前任务和状态；分支复杂时设局部索引，增删移动文档时同步维护。
- Spec 与实现冲突时判断实现偏差还是 Spec 漂移；新结论更新正式文档，失效结论删除或改写。未决讨论不进入长期 Spec。
- 仓库缺少索引或稳定 Spec 时，读取 `references/project-onboarding.md`。

## 请求分类

| 类型 | 适用条件 | 处理 |
|---|---|---|
| 讨论/规划 | 询问设计、风险、规则或方案 | 读取必要材料并判断；无实施要求不改代码 |
| 细节任务 | 目标清晰、责任范围明确，可直接定位修改验证 | 直接完成，不因多文件或需要测试而升级 |
| 迭代任务 | 跨模块、外部契约、数据模型、持久化、核心架构、复杂验收或多 Agent 协作 | 执行下方迭代流程 |

实际范围扩大时重新分类。定位时先查业务权威责任层和所有消费入口，不只修报错位置。

## 实施约束

- 同一业务语义只保留一个权威责任层；外部契约变化同步更新 Spec/API。
- 用户可见阈值、数量、排序、距离或兼容规则必须有现成契约、用户决定或可唯一推导的依据；不通过模糊 fallback、扩大阈值或新增兼容分支掩盖需求缺口。
- 新模型/机制成为内部权威路径后，旧实现若无独立业务、协议或兼容职责，应删除或吸收；不为复用旧加工链将新模型转换回被取代的旧表示。真实系统边界可保留 adapter。
- 变更的验证范围依实际风险选择：局部定向测试、单模块构建/测试、跨模块契约或集成、持久化/协议迁移与运行验证。只有必要才执行全量测试。
- Bug 与用户可见行为修改覆盖原始失败案例。截图、输入输出或复现步骤直接用于回归；lint/typecheck/build 不能替代行为和契约验证。

## 迭代流程

### 1. 定界与建档

读取必要索引、Spec、API 和代码，确定目标、范围、权威责任层、依赖风险、设计决定、验收标准、验证范围、文档更新项和旧机制取缔项。

创建 `yyyy-mm-dd-简短描述.md` 任务文档，登记 Agent 分工与测试所有权，并更新索引状态。任务文档创建和主要实现不得并行。

若引入替代性权威路径，明确需要退出的旧业务、解析/转换、配置、SQL、协议入口、测试或文档职责；列语义边界，不需要预列所有具体文件。保留兼容层须有真实理由及退出条件。

### 2. 审阅与用户决策

父 Agent 在主要实现前审阅任务边界、设计、分工、验收、验证及取缔项，并向用户简要说明方案、明确不做的内容、交付物和必要决策。

用户已经明确要求执行且没有真实待决策项时，无需重复确认。以下情况暂停受影响实施以确认：结果关键歧义、范围扩大、不可逆操作、兼容性破坏、核心产品/架构分叉、既有决定冲突、新增未批准的取缔范围、需自行定义外部可见规则。

用户审批的是旧职责退出的语义边界，不是其内部每个文件或函数的删除动作；已批准范围内的死代码、配置、SQL、测试和文档可依实际依赖清理。

### 3. 分工与实施

父 Agent 协调并审核，不替代任务中已声明的主要实现或测试角色。同一业务闭环默认由同一实现 Agent 完成；仅在任务与交付物相互独立、不共同修改关键文件时并行。API、协议、持久化和核心依赖优先串行。

独立 Test Agent 存在时明确区分 `实现自测` 和 `独立验收`：实现 Agent 做最小自测，测试 Agent 从 Spec/验收标准独立推导正式用例。不能仅重跑实现测试宣称独立验收，也不应永久制造重复测试。

按已批准范围完成实现及旧职责清理；发现新的独立取缔范围时重新决策，不静默扩展。

### 4. 验收与收口

测试 Agent 覆盖原始失败、明确输入输出、真实入口、相邻边界、契约和失败路径。旧机制取缔项另需验证旧生产入口及其配置、SQL、协议、表示和测试不再承担被取代职责；关键词检索只是辅助证据。

父 Agent 审阅交付物和已有有效证据，不重复正式测试。验证后有相关代码变化时重跑受影响范围。

完成后更新任务记录、索引和状态、长期 Spec、API 及失效描述，并按项目要求提交 Git。状态以真实进度为准，可使用 `待开始 → 待关键决策 → 进行中 → 实现完成待测试 → 测试完成待收口 → 已完成` 或项目等价状态。

**仅在用户明确要求归档时**，将任务文档移至 `迭代任务/归档/` 下按日期或功能组织的位置；同步索引。

## 完成检查

- 是否遵循最小流程，并让稳定结论落入权威 Spec？
- 外部规则有来源，新路径已接管职责，旧机制按批准范围退出？
- Agent 分工和独立测试所有权落实，原始失败及实际影响范围得到验证？
- 任务状态、契约、索引和正式文档同步收口？
