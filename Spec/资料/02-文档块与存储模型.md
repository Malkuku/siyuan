# 02：文档、块与存储模型

整理：2026-10-14。依据当前仓库源码、格式文档及只读观察的普通笔记 `.sy` 文件。

## 三种表示，同一份内容

| 表示 | 作用 |
|---|---|
| 磁盘上的 `.sy` | 保存文档原始内容：序列化为 JSON 的 Lute AST |
| 内存中的 `parse.Tree` | 包装文档根节点及笔记本、文件路径等上下文 |
| SQLite 的块记录 | 从文档树提取内容和关系，提供可重建的查询索引 |

普通笔记的源内容在文件中，数据库不是唯一内容来源。格式依据见 [SY 格式](../../docs/SY-FORMAT.zh-CN.md)，磁盘分工见 [工作空间](../../docs/WORKSPACE.zh-CN.md)。

## 内容树与目录树

“文档目录树”描述笔记本中多篇文档的层级；“文档内容树”描述一篇文档内部的标题、段落和列表。函数参数中的 `parse.Tree` 属于后者及其上下文。

下面的短 ID 是教学示例，不是规范 ID：

```json
{
  "ID": "doc-1",
  "Type": "NodeDocument",
  "Properties": {"title": "学习计划"},
  "Children": [
    {
      "ID": "paragraph-1",
      "Type": "NodeParagraph",
      "Children": [{"Type": "NodeText", "Data": "学习 MySQL"}]
    }
  ]
}
```

`Children` 的递归嵌套已经表达树结构，不必再出现名为 `tree` 的字段。读取后 `Tree.Root` 指向根节点，加载过程补充 `Box`、`Path` 等信息，见 [读取实现](../../kernel/filesys/tree.go)。`Node` 是其中一个节点，`Tree` 提供整篇文档的访问入口和上下文。

## 节点类型与嵌套

`Type` 描述内容语义或结构角色；字体、颜色等外观由渲染和样式处理。节点包括块、内联内容和标记，不是每个 JSON 节点都是块。

实际学习样本的结构可缩小为：

```text
NodeDocument
├─ NodeHeading：“每日计划”
└─ NodeList
   └─ NodeListItem：整个 Day1-2 列表项
      ├─ NodeParagraph
      │  └─ NodeTextMark：“Day1-2”
      └─ NodeList：任务列表
         └─ NodeListItem
            ├─ NodeTaskListItemMarker：勾选标记
            └─ NodeParagraph
               └─ NodeText：“MySQL安装配置”
```

任务属于外层列表项，不属于“Day1-2”文本节点。标题与后续列表在 AST 中可以同级，阅读中的章节归属不等于 JSON 的父子关系。

## Lute 与索引转换

思源依赖 [Lute](https://github.com/88250/lute) 文档引擎，见 [go.mod](../../kernel/go.mod)。CommonMark/GFM 描述 Markdown 语法，Lute 定义具体 AST 表示；`.sy` 按 Lute 与思源约定保存，不是通用富文本 JSON 标准。当前学习只需理解转换职责，不要求掌握解析器内部规则。

[buildBlockFromNode](../../kernel/sql/database.go) 从 AST 节点及所属文档树构建 `sql.Block` 索引对象：

| 字段 | 来源或含义 |
|---|---|
| `id` | 当前块 ID，连接 AST 块与数据库记录 |
| `root_id` | 文档根 ID |
| `parent_id` | 索引中的父关系；可能根据标题关系加工，不保证等于 AST 直接父节点 |
| `box`、`path` | 所属笔记本、文件路径 |
| `content` | 从节点及其内部内容提取的索引文本 |
| `markdown` | 导出的 Markdown 表示 |

段落包含文字，但文字可能分布于 `NodeText.Data`、`NodeTextMark.TextMarkTextContent` 等子节点字段中。`Children` 是节点数组，提取文本和导出 Markdown 都需要按节点类型处理。例如加粗文字分别生成普通索引文本与带 `**` 的 Markdown。

构建索引对象尚不是 SQL 写入。块关系、引用关系等分别进入 `blocks`、`refs` 等表，见 [数据库定义](../../kernel/sql/database.go)。

## 块身份与 AI 操作

块 ID 使段落等内容可单独定位和操作；移动与复制的身份语义需要区分。跨文档移动并保留自身身份时，所属文档和父关系会改变。

AI 看到的表示由工具决定。当前 [MCP 块工具](../../kernel/mcp/tools/block.go) 可返回块信息、Markdown、子块或层级路径；移动提交块 ID、目标父 ID 和可选的前置块 ID，由内核维护结构。AI 不必直接修改 JSON 或 SQL。

Markdown 及编辑器扩展也能提供链接、锚点或块引用。比较模型时关注身份、关系维护和操作接口；不能仅由 MD/JSON 格式判定编辑能力。
